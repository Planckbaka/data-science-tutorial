# 12-06 系统设计面试题

> **适用岗位**: B站商业化 AI Agent 开发工程师
> **考察重点**: 架构设计能力、技术选型、可扩展性、实际工程经验

## 题目一：设计一个 Agent 平台（类似 Dify/Coze）

### 需求

- 用户可以通过可视化界面搭建 Agent 工作流
- 支持多种 LLM 后端（OpenAI、Claude、通义千问、本地模型）
- 支持工具注册、RAG 知识库、对话记忆
- 需要支持并发调用，日均 100 万次 Agent 调用

### 架构设计

```
┌──────────────────────────────────────────────────────┐
│                    前端 (React/Vue)                    │
│  ┌──────────┐  ┌──────────┐  ┌───────────────────┐   │
│  │ 工作流编辑器│  │ 知识库管理│  │ 监控/日志 Dashboard│   │
│  └──────────┘  └──────────┘  └───────────────────┘   │
└───────────────────────┬──────────────────────────────┘
                        │ REST/WebSocket
┌───────────────────────▼──────────────────────────────┐
│                  API Gateway (Nginx/Kong)              │
│  - 限流、鉴权、负载均衡                                 │
└───────────────────────┬──────────────────────────────┘
                        │
┌───────────────────────▼──────────────────────────────┐
│               Agent 编排引擎 (核心)                     │
│  ┌──────────┐  ┌──────────┐  ┌──────────────────┐    │
│  │ DAG 解析器│  │ 节点执行器│  │ 状态管理 (Redis)  │    │
│  └──────────┘  └──────────┘  └──────────────────┘    │
│  - 将可视化工作流转为 DAG                               │
│  - 按拓扑序执行节点                                     │
│  - 支持条件分支、循环、并行                              │
└──────┬──────────┬──────────┬─────────────────────────┘
       │          │          │
┌──────▼───┐ ┌───▼────┐ ┌───▼────────────┐
│ LLM 网关  │ │ Tool   │ │ 知识库服务      │
│          │ │ Registry│ │                │
│ - 多模型  │ │ - API  │ │ - Embedding    │
│   路由    │ │ - DB   │ │ - Vector Store │
│ - 限流   │ │ - 搜索  │ │ - Reranker     │
│ - 降级   │ │ - 自定义│ │ - Chunk 管理   │
└──────────┘ └────────┘ └────────────────┘

┌──────────────────────────────────────────────────────┐
│                    基础设施层                           │
│  ┌──────┐  ┌──────┐  ┌──────┐  ┌──────┐  ┌───────┐  │
│  │MySQL │  │Redis │  │MQ    │  │S3/OSS│  │Prom+  │  │
│  │元数据 │  │缓存   │  │异步队列│  │文件   │  │Grafana│  │
│  └──────┘  └──────┘  └──────┘  └──────┘  └───────┘  │
└──────────────────────────────────────────────────────┘
```

### 关键设计决策

| 模块 | 方案 | 理由 |
|------|------|------|
| **编排引擎** | DAG + 状态机 | 支持复杂分支/循环，可暂停恢复 |
| **LLM 网关** | 统一接口 + 模型路由 | 屏蔽多模型差异，支持降级策略 |
| **知识库** | Embedding + FAISS/Milvus | FAISS 适合百万级，Milvus 适合亿级 |
| **异步执行** | 消息队列 (Kafka/RabbitMQ) | 削峰填谷，支持重试 |
| **状态持久化** | Redis + MySQL | Redis 缓存运行时状态，MySQL 持久化 |
| **监控** | LangSmith / Prometheus + Grafana | 链路追踪 + 系统指标监控 |

### 扩展性考虑

- **水平扩展**: 编排引擎无状态化，状态存 Redis，支持多实例部署
- **插件机制**: 工具/节点通过 Plugin 注册，支持热加载
- **多租户**: 租户隔离（数据库/向量库/API Key 级别）
- **灰度发布**: Agent 版本管理，支持 A/B 测试

## 题目二：设计一个 RAG 系统（支持百万级文档）

### 需求

- 接入 B站商业化文档（投放指南、API 文档、FAQ、案例）
- 支持百万级文档，查询延迟 < 2s
- 支持多格式（PDF、Word、Markdown、HTML）
- 支持增量更新和实时索引

### 架构设计

```
文档入库流程:
┌──────┐    ┌──────────┐    ┌──────────┐    ┌──────────┐
│ 文档  │───→│ 解析服务  │───→│ Chunking │───→│Embedding │
│ 上传  │    │PDF/Word/ │    │ 分块策略  │    │ 向量化   │
│      │    │ HTML解析  │    │          │    │          │
└──────┘    └──────────┘    └──────────┘    └────┬─────┘
                                                  │
                                          ┌───────▼───────┐
                                          │   向量数据库    │
                                          │ (Milvus/FAISS) │
                                          │ + 元数据索引    │
                                          └───────────────┘

查询流程:
┌──────┐   ┌──────────┐   ┌──────────┐   ┌──────┐   ┌──────┐
│用户   │──→│Query     │──→│ 向量检索  │──→│Rerank│──→│ LLM  │
│提问   │   │改写/扩展  │   │ Top-K    │   │重排序 │   │ 生成  │
└──────┘   └──────────┘   └──────────┘   └──────┘   └──────┘
```

### 关键技术选型

| 环节 | 方案 | 说明 |
|------|------|------|
| **文档解析** | Unstructured / PyPDF2 + python-docx | 支持多格式，表格/图片 OCR |
| **分块策略** | 递归分块 (RecursiveCharacterTextSplitter) | chunk_size=512, overlap=64, 按语义边界 |
| **Embedding** | bge-large-zh / text-embedding-3-small | 中文选 bge，英文选 OpenAI |
| **向量库** | Milvus (百万级) | 支持过滤、分区、增量更新 |
| **检索** | 混合检索 (Dense + Sparse) | BM25 关键词 + 向量语义，倒数融合 (RRF) |
| **重排序** | bge-reranker-large / Cohere Rerank | 交叉编码器精排，显著提升准确率 |
| **生成** | GPT-4 / Claude / Qwen | 带引用来源的 faithfulness 生成 |

### 优化策略

1. **查询改写**: 用 LLM 将口语化查询改写为精确检索 query
2. **HyDE**: 先让 LLM 生成假设性答案，用答案的 embedding 检索
3. **多路召回**: 向量检索 + BM25 + 知识图谱，RRF 融合
4. **缓存**: 热门问题 Redis 缓存，TTL 1 小时
5. **增量索引**: 文档变更通过消息队列触发重新 embedding

### 评估体系

- **Retrieval**: Recall@5, MRR, NDCG
- **Generation**: Faithfulness (是否基于检索内容), Relevance (是否回答问题)
- **End-to-End**: 人工标注 Golden Dataset，定期回归测试

## 题目三：设计 B站广告投放 Agent 系统

### 需求

- 广告主通过自然语言描述投放需求
- Agent 自动制定投放策略（预算分配、人群定向、出价）
- Agent 监控投放效果，自动优化
- 支持多个广告主同时使用

### 架构设计

```
┌─────────────────────────────────────────────────────┐
│                  广告主交互层                          │
│  ┌──────────┐  ┌──────────┐  ┌──────────────────┐   │
│  │ 自然语言  │  │ Dashboard│  │ 消息通知 (站内信) │   │
│  │ 对话界面  │  │ 数据看板  │  │                  │   │
│  └─────┬────┘  └──────────┘  └──────────────────┘   │
└────────┼────────────────────────────────────────────┘
         │
┌────────▼────────────────────────────────────────────┐
│              Agent 编排层 (LangGraph)                 │
│                                                      │
│  ┌──────────┐   ┌──────────┐   ┌──────────────┐     │
│  │ 意图理解  │──→│ Supervisor│──→│ 结果聚合     │     │
│  │  Agent   │   │  Agent   │   │ + 人工确认    │     │
│  └──────────┘   └────┬─────┘   └──────────────┘     │
│                      │                               │
│         ┌────────────┼────────────┐                  │
│         ▼            ▼            ▼                  │
│  ┌──────────┐ ┌──────────┐ ┌──────────┐             │
│  │ 数据分析  │ │ 策略制定  │ │ 素材生成  │             │
│  │  Agent   │ │  Agent   │ │  Agent   │             │
│  └──────────┘ └──────────┘ └──────────┘             │
└──────────────────────┬──────────────────────────────┘
                       │
┌──────────────────────▼──────────────────────────────┐
│                   工具 & 数据层                        │
│  ┌──────┐  ┌──────┐  ┌──────┐  ┌──────┐  ┌───────┐ │
│  │广告API│  │数据仓库│  │人群包 │  │素材库 │  │知识库  │ │
│  │投放管理│  │Hive/CK│  │DMP   │  │生成   │  │RAG   │ │
│  └──────┘  └──────┘  └──────┘  └──────┘  └───────┘ │
└─────────────────────────────────────────────────────┘
```

### 各 Agent 职责

| Agent | 职责 | 输入 | 输出 |
|-------|------|------|------|
| **意图理解** | 解析广告主需求 | 自然语言描述 | 结构化投放需求 |
| **数据分析** | 分析历史数据、行业 benchmark | 广告主 ID + 行业 | 数据洞察报告 |
| **策略制定** | 预算分配、人群定向、出价策略 | 需求 + 数据洞察 | 投放计划 JSON |
| **素材生成** | 生成广告文案/标题/描述 | 产品信息 + 定向人群 | 多套素材方案 |
| **Supervisor** | 协调各 Agent、质量把关 | 各 Agent 输出 | 最终投放方案 |

### 关键设计点

1. **Human-in-the-loop**: 投放方案需广告主确认后才执行
2. **预算安全**: 硬性预算上限，超支自动暂停
3. **效果监控**: 定时 Agent 检查 ROI/CPA 指标，异常自动告警
4. **策略回退**: 效果不达标自动回退到上一个有效策略
5. **多租户隔离**: 每个广告主独立的 Agent 状态和数据权限

### 面试回答框架

回答系统设计题时，按这个顺序:

1. **需求澄清** (1-2分钟): 确认规模、核心功能、非功能需求
2. **高层架构** (3-5分钟): 画出核心模块和数据流
3. **核心模块详设** (5-8分钟): 挑 1-2 个最复杂的模块深入
4. **技术选型** (2-3分钟): 说明每个选型的理由和 trade-off
5. **扩展与优化** (2-3分钟): 缓存、分库分表、监控、降级
